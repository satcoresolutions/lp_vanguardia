## 🧠 Sobre el proyecto

**Landing Page Vanguardia** es una plantilla web desarrollada por **SatCore Solutions** para construir páginas de aterrizaje modernas, visualmente atractivas y orientadas a objetivos comerciales.

El proyecto proporciona una base reutilizable para presentar productos, servicios, marcas o iniciativas digitales, con una estructura organizada en componentes y secciones independientes.

Su arquitectura busca facilitar la personalización visual, el mantenimiento del código y la incorporación progresiva de nuevas funcionalidades sin comprometer la organización general del proyecto.

La plantilla está construida con Next.js, TypeScript y Tailwind CSS, utilizando componentes reutilizables y una separación de responsabilidades entre interfaz, secciones y utilidades.

### Propósito

- Facilitar la creación de landing pages profesionales.
- Mejorar la presentación de productos y servicios.
- Favorecer la captación de clientes potenciales.
- Proporcionar una base escalable para nuevos proyectos web.
- Mantener una arquitectura consistente y fácil de mantener.
- Permitir la personalización de contenido, imágenes y elementos de interfaz.

```bash

cd lp_vanguardia
```

### 2. Instalar las dependencias

```bash

```

Este comando instala las dependencias definidas por el proyecto.

### 3. Iniciar el servidor de desarrollo

```bash
npm run dev
```

Abre la aplicación en:

[http://localhost:3000](http://localhost:3000)

### 4. Compilar para producción

```bash

```

### 5. Iniciar la versión de producción local

Después de una compilación exitosa:


## 🧱 Arquitectura

La plantilla utiliza una organización modular dividida en tres capas conceptuales.

### 1. UI Layer

Contiene los elementos de interfaz reutilizables, como botones, etiquetas, tarjetas y componentes visuales.

**Objetivo:** mantener una presentación consistente y reducir la duplicación de código.

### 2. Sections Layer

Contiene las secciones que conforman la landing page: presentación principal, características, catálogo, testimonios, llamadas a la acción y pie de página.

**Objetivo:** facilitar la composición, reorganización y personalización de las páginas.

### 3. Lib Layer

Contiene utilidades y funciones compartidas que pueden ser utilizadas por diferentes componentes.

**Objetivo:** centralizar lógica auxiliar y mantener los componentes más claros.

### Beneficios

- Reutilización de componentes.
- Separación de responsabilidades.
- Mantenimiento simplificado.
- Personalización por secciones.
- Evolución progresiva de la arquitectura.

## 🔐 Seguridad

La seguridad debe considerarse durante el desarrollo, la configuración y el despliegue.

### Variables de entorno

Las credenciales y claves privadas deben almacenarse en variables de entorno y no directamente en el código fuente.

Buenas prácticas:

- No subir archivos `.env.local` ni otros archivos con secretos.
- Mantener estos archivos excluidos mediante `.gitignore`.
- No publicar claves privadas en documentación, capturas o registros.
- Utilizar variables descriptivas.
- Rotar las credenciales si se exponen accidentalmente.
- Mantener las dependencias actualizadas.

### Formularios e integraciones

Si se incorporan formularios, API o servicios externos, deben implementarse validación de datos, controles contra abuso y permisos adecuados en el servidor.

El prefijo `NEXT_PUBLIC_` debe reservarse para variables que puedan exponerse al navegador. **Nunca debe utilizarse para una clave secreta.**
